# Contributing

Use Python 3.10+ and the standard library. Keep changes small and add synthetic
tests for changed parsing, path safety, decisions and CLI behavior.

Run `python3 -B -m unittest discover -s tests -v` before proposing a change.
Do not commit real drafts, client records, source archives, secrets or generated
approvals. Link policy changes to relevant primary sources and state whether a
rule is a local convention, contextual guidance or a technical requirement.

Do not turn missing evidence into a pass, waive automatic failures through review
receipts, invent a numeric Google authority score, or make a writer its own approval
authority. Preserve unknown versus adverse evidence and source provenance.

Changes to the catalog/engine invalidate review fingerprints. Document them in
CHANGELOG.md. Do not relabel independent evaluation cases simply to make tests pass.
Additional dependencies, integrations or network behavior require explicit review.
